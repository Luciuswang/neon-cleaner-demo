## Primary-source findings

Epic's [UE 5.8 launch announcement, June 23, 2026](https://www.unrealengine.com/news/unreal-engine-5-8-is-now-available)
confirms Experimental MCP, Experimental **Direct Mesh Controls (DMC)**, Beta
Control Rig Physics and a new Control Rig Dynamics solver. DMC means controls
represented on skeletal mesh surfaces; it is not an AI motion generator. The
same announcement labels Movie Render Graph production-ready. These features
do not require an engine-version migration for this 5.8.1 project.

The [official Unreal MCP documentation](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor?application_version=5.8)
identifies `ModelContextProtocol` as the plugin identifier and explains the
separate toolset registry. Calls execute serially on the game thread, so workers
must not issue concurrent mutation calls. Default connectivity is local HTTP
at `127.0.0.1:8000/mcp`; Epic says there is no authentication layer and it is not
designed for remote access. If adopted later, use only bounded local tools and
the existing single-writer policy. Transport integration itself is not a visual
quality improvement.

[Epic's PCG/LLM guidance](https://dev.epicgames.com/documentation/unreal-engine/working-with-pcg-and-llms-using-unreal-mcp-in-unreal-engine)
is also explicitly Experimental. It recommends loading the PCG graph skill,
grounding edits in working example graphs, adapting existing patterns and
executing in short supervised steps. For this project, source building material
restoration precedes graph-based facade variation; procedural placement should
consume accepted modules rather than multiply current placeholder buildings.

[Full Body IK documentation](https://dev.epicgames.com/documentation/en-us/unreal-engine/control-rig-full-body-ik-in-unreal-engine)
describes effectors, per-bone stiffness, preferred angles and rotation limits.
Those are directly relevant to the rejected wrist posture and seat/foot
constraints. The implementation still needs measured anatomical frames and
proper finger skinning; zero wrist-target error alone is insufficient.

[Epic's ML Deformer workflow](https://dev.epicgames.com/documentation/en-us/unreal-engine/how-to-use-the-machine-learning-deformer-in-unreal-engine)
requires a skinned character plus externally generated corrected deformation
data. Neural Morph learns runtime approximations from this training data.
[Framework guidance](https://dev.epicgames.com/documentation/en-us/unreal-engine/ml-deformer-framework-in-unreal-engine)
specifically warns against production use of the Vertex Delta example model.
The high Kelly source is missing production textures/groom dependencies; ML
Deformer is not a substitute for restoring them.

[Semantic Search documentation](https://dev.epicgames.com/documentation/unreal-engine/semantic-search-in-unreal-enigne)
states that indexing can send thumbnails/metadata to configured captioning and
embedding services. Its provider keys are stored in per-user config in clear
text. Therefore it should not be silently enabled on the private Kelly library
or included in cross-PC configuration backups. No such setup was performed.

## Concrete work to use now

1. Keep the existing C++/Python commandlet route for inspection, asset manifests,
   build checks and repeatable changes. The shipped
   `Experimental/Toolsets/AnimationAssistantToolset/Content/Python/animation_toolset/toolsets/controlrig.py`
   supplies engine-matched examples; use them as references without activating
   the assistant stack.
2. Build a separate Kelly Control Rig candidate using the actual skeleton and
   measured grip, footpeg and seat frames. Start with constrained arm/leg
   solving and a pelvis frame. Calibrate fingers separately around actual grip
   axes/radii; validate skin weights before further curl adjustments. Retain
   the existing active character until the candidate passes contact review.
3. Restore city mesh/material assignments before PCG experimentation. Reuse an
   existing PCG graph only if repeated module placement becomes the concrete
   bottleneck; keep fixed seeds, bounded instance counts and reversible outputs.
4. Continue respecting the no-desktop-screenshot / locked-screen workflow.
   Scripted topology, bone transforms, contacts, animation timing and logs can
   be checked independently. Such checks cannot award cinematic visual PASS.
   Offscreen GPU rendering, if later requested, must be tested on this locked
   workstation rather than assumed reliable.

No current evidence supports replacing the project's tested pipeline with an
unattended AI editor agent, or accepting current assets because UE now includes
AI integrations. Existing CINEMATIC REWORK / AI VIDEO BLOCKED findings remain.
