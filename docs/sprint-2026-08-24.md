# Sprint Plan - 2026-08-24

## Sprint Objective

Create a presentable Neon Cleaner prototype loop this week:

```text
AI opening / bridge clip -> UE Lin Xia rider -> gameplay takeover -> short chase
```

The sprint is successful when the project can show a coherent 30-60 second
prototype where the player takes control of Lin Xia without an identity or
camera shock.

## Current Starting Point

- Branch: `codex/character-continuity-pipeline`.
- UE engine: 5.8 local install.
- UE project: `ue/NeonCleanerUE/NeonCleanerUE.uproject`.
- Startup preview map: `/Game/LinxiaPreview/LVL_Linxia_CharacterPreview`.
- Playable source character: `PlayablePhaseCharacter` using Epic/Fab
  `Paragon: Phase`.
- Last known state: playable preview passed local smoke test and was pushed to
  GitHub as commit `ab8d58f`.

## Weekly Milestones

### Monday: Playable Lin Xia Baseline

Goal: make the current heroine preview stable enough to build on.

Tasks:

- Pull latest branch state and confirm clean repo.
- Open / validate the UE project and startup map.
- Verify `PlayablePhaseCharacter` possession, camera, movement, jump, and run
  animation direction.
- Re-tune hair / lighting only if the current preview still reads incorrectly.
- Capture at least one UE reference image into
  `source/reference/linxia/ue-captures/`.

Exit gate: Gate 1 from `docs/agent-production-workflow.md`.

### Tuesday: Rider And Motorcycle Proxy

Goal: stop showing Lin Xia as a standalone display character and place her in
the intended gameplay identity.

Tasks:

- Build or assemble a black electric motorcycle proxy.
- Place Lin Xia on or beside the proxy with a rear / side-rear readable pose.
- Create a low chase camera that can become the gameplay camera.
- Avoid final-rig complexity; prioritize silhouette and scale.

Exit gate: Gate 2.

### Wednesday: Short Chase Corridor

Goal: create a playable route that proves the game loop.

Tasks:

- Create a 30-60 second elevated road / industrial route.
- Add wet surface, damaged barriers, debris, and readable path direction.
- Add a target convoy or objective ahead.
- Add simple avoidable obstacle beats.
- Connect player start, camera, and control handoff.

Exit gate: Gate 4 draft pass.

### Thursday: AI / UE Handoff Pass

Goal: regenerate or revise the AI bridge content around the UE first frame.

Tasks:

- Capture UE reference pack: rider, motorcycle, chase camera, handoff frame.
- Update AI video prompts so the ending frame matches the UE camera.
- Use occlusion, rain splash, flare, or smoke to hide imperfect continuity.
- Replace bridge media only after the UE first frame is locked.

Exit gate: Gate 3.

### Friday: Demo Packaging And GitHub Handoff

Goal: leave a complete, recoverable prototype.

Tasks:

- Record a demo clip.
- Run a final smoke test.
- Update `docs/handoff.md` with exact run / restore steps.
- Confirm Marketplace assets are excluded and Git LFS is healthy.
- Commit and push the week milestone.

Exit gate: Gate 5.

## First Slice For Today

Producer tasks:

1. Run repo and UE project checks.
2. Rebuild if needed.
3. Run preview validation scripts.
4. Open the preview map or run a command-line smoke test.
5. Fix blocking character / camera / animation issues.

QA Director checks:

1. Character is Player 0 controlled.
2. `W`, `A`, `S`, `D` directions match camera-relative expectation.
3. Run animation direction matches movement.
4. Character does not read as sliding during simple movement.
5. Hair / face lighting is acceptable for reference capture.
6. No public-repo-only file is required without being documented.

Definition of done:

- The preview can be opened and operated.
- The result is good enough to start the motorcycle proxy slice.
- Any known defects are documented as non-blocking.

## QA Policy For This Sprint

- No AI video regeneration before the UE reference pack receives QA `PASS`.
- No bridge movie replacement before the AI final frame and UE first frame
  receive QA `PASS`.
- No external demo claim before startup playback, `Take Control`, automatic input
  return, gameplay possession, and GitHub restore notes receive QA `PASS`.
- `CONDITIONAL PASS` is allowed only for prototype polish issues, not for
  control, identity-source, camera-direction, or restore-path issues.
